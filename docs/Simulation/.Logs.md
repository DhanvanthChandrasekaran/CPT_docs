### ".sdf" file conventions
The model is aligned towards the positive x axis, that is the forward of the drone is positive x axis and upward is positive z axis and by extenstion the y axis is towards the left side of the drone.

### Editing ".sdf" files
In Gazebo we can define our own custom simulation models in a ".sdf" file and if our geometry requires more than just premitive shapes or if we already have an accurate CAD diabgram of the simulation model then we can export that CAD model into ".obj", ".dae", or ".stl" files and add it into our simulation file like ```<uri>model://Custom_Drone/meshes/chassis.obj</uri>```

I choose to export it into ".obj" file because ".stl" files only contain geometry and none of the color and texture info, and ".dae" does both of that but Fusion 360 does not export on that format. the textures for ".obj" file are seperately stored in a ".mlts" file. So esentially I have 2 files, 1 for the geometry and 1 for the color and texture of model. 


I had to scale down the obj file a 100 times becuase I think the units might have been missmatched. 
but the propeller files are on the correct scale

The Chassis and the Rotors (propellers) are defined as seperate links (objects). 
Here by Chassis I just mean all the parts of the drone that are static and don't have any relative motion. That is the entire drone appart from the props
We have to define them seperately because during simulation there has to be relative motion between these parts. That is the propellers have to rotate for the drone to fly and to do that in simulation we need them to be seperate links

So essentially I would have 5 links defined in the simulation file. One for the Chassis and 4 Rotors. 


The Collision Geometry for the rotors for the x500 drone was defined as a box and the problem with this is that as simulation progresses and the rotors rotate the collision geometry also has to rotate. The CPU would waste compute on rotating a long cuboid box. So to improve that I just changed the propeller collision geometry to be a Cylinder. This does not mean the collision boundary would not be rotated during the simulation, it would be rotated but the shape would be same and Gazebo has like a 2 step process to simulate collision. First it does a broad overview called Axis-Aligned Bounding Box (AABB) and then if these brad bounding boxes collide then it looks closely at them and cince the shape of cylinder when rototed does not change the AABB also won't change hence less compute is wasted. (or atleast that is why AI overload says).


There is also this interesting parameter called "min_depth" in the collision tab. It is defined like this
```<min_depth>0.001</min_depth>```
This just says that it is fine until objects intersect within 1mm. This prevents jitter in the simulation.
